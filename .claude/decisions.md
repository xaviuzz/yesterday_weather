# Decisions

Each decision and its why. Replace a bullet when the code changes it; do not stack a correction beside it.

- Package `yesterday_weather` (cargo wants snake_case); the folder is `yesterdayWeather`.
- Readability for a Rust learner: explicit types where inference hides what a value is, one concept per small function or type, names that say the domain term (`Daypart`, `ThermalSensationChange`), no macro or trait tricks while a plain construct works.
- The global conventions (explaining variables, explicit loops, one return, no ternary, no comments) apply. Where Rust forces an idiom (`match`, `?`, `Option`, iterators over borrowed data), prefer the most plain form and say so here when it is a decision.
- No dependencies yet. Each crate is added when a failing test needs it, with its why recorded here. The reference proposes `ureq`, `serde`, `serde_json`, `anyhow`, `clap`, `jiff` as candidates.
- Output language is Spanish only. A second language earns a seam by the rule of three.
- Domain code depends on the `WeatherSource` trait, implemented by the Open-Meteo adapter. Why: tests of the domain run on a fake without network or clock. One `#[ignore]` integration test hits the real API with Valencia (39.47, -0.38).
- `WeatherSeries` answers "now and yesterday at this hour". Why: the 24-hour lookup is a domain rule, not a JSON detail. It is built from the hourly values (yesterday 00:00 first) and the current hour as a plain `u8`, and `change()` returns a `ThermalSensationChange`. `new` returns `Result` and rejects a series shorter than `24 + current_hour + 1` with `WeatherError::IncompleteSeries`, so an invalid series never exists. The length check also rejects hours above 23 in practice; an `HourOfDay` type waits for the rule of three.
- `WeatherSource` has one method, `weather_series(&self) -> Result<WeatherSeries, WeatherError>`, and takes no `Location`. Why: the adapter holds its coordinates from its own constructor, so the domain never sees them; returning a `WeatherSeries` keeps "an invalid series never exists" true at the boundary. Step 4b runs before step 5.
- `WeatherError::SourceUnavailable` (no payload) is added in 4b, tested with a failing fake. Why: the use case must propagate source errors. A payload waits until something reads it.
- The use case is `YesterdayComparison<S: WeatherSource>`, a struct holding the source, with `summary(&self) -> Result<Summary, WeatherError>`. Why: generics avoid `Box<dyn>` and the heap, two concepts a learner does not need yet; behavior lives with the data it uses.
- `Location::from_args(args: &[String]) -> Result<Location, WeatherError>` takes the arguments after the program name (`main` passes `env::args().skip(1)`). Why: `std::env` stays out of the library and tests pass plain arrays. `--lat` and `--lon` are both required, in either order, no defaults; latitude within -90..=90, longitude within -180..=180; exactly two flag-value pairs, so unknown and repeated flags fall out as errors. One `WeatherError::InvalidArguments` without payload, split by cause when step 8 needs to say it. `Location` has private fields and public `latitude()` and `longitude()` because the adapter reads them. No `Latitude`/`Longitude` newtypes until the rule of three.
- Where clippy's `collapsible_if` suggests let-chains (`if let ... && ...`, edition 2024), use a `match` arm with a guard instead. Why: a guard is an older, plainer construct that a learner meets in every Rust book; let-chains wait until they feel natural.
- Crate is `lib.rs` plus a thin `main.rs`. Why: tests in `tests/` see only the public library.
- `lib.rs` holds only `mod` declarations and `pub use` re-exports; each domain concept has its own file in `src/`, named after it in snake_case (`thermal_sensation_change.rs`). Why: a learning project needs structure at file level, and a 250-line `lib.rs` hid it. The re-exports keep the public path flat (`yesterday_weather::Summary`), so tests did not change. `Threshold` and `THRESHOLDS` stay private in `thermal_sensation_change.rs`, their only user. `degrees()` on `Celsius` and `ThermalSensationChange` is `pub(crate)` because `Summary` and `ThermalSensationChange` now live in other modules; tests still cannot reach it. A new concept gets a new file, not more lines in an existing one.
- Errors are an own `WeatherError` enum, no `anyhow`. Why: learning Rust's error model. Revisit when three or more variants only propagate.
- Arguments parsed by hand from `std::env::args`, no `clap`. Why: two flags.
- "Yesterday at this hour" is found by position (`i - 24` in the hourly series), no date crate. Known limitation: the autumn clock change (25 October 2026 in Spain) shifts it by one hour. `jiff` enters when a failing test needs date arithmetic.
- Lines are at most 80 characters, enforced by `max_width = 80` in `rustfmt.toml`. Why: long lines hurt visual reading. `cargo fmt` wraps them; a line it cannot wrap (a long string) is split by hand when possible.
- `ThermalSensationChange` (renamed from `FeelsLikeDifference`, which read as "feels like difference"). Why: "sensación térmica" is the term in the Spanish output, and `between(yesterday, now)` is a signed change over time. Open-Meteo's `apparent_temperature` stays inside the adapter (step 6).
- No public item exists only for tests. Tests in `tests/` see the public library and assert on behavior (`band()`, `Summary::text()`), never on internals. `Celsius` has a private field and one public constructor, `Celsius::new`, which the adapter (step 6) also needs. `degrees()` on `Celsius` and on `ThermalSensationChange` is `pub(crate)`, never `pub`. Rust has no monkeypatching; the substitution seam is a trait (`WeatherSource`). Unit tests inside `src/` (`#[cfg(test)] mod tests`) are the option if a private rule ever needs its own test.
- The temperature bands are a `THRESHOLDS` table of `Threshold` rows (limit, warmer band, colder band), walked in ascending order with each reached row overwriting the band. Why: each limit is written once and the warmer/colder symmetry is explicit. A limit belongs to the upper band (`>=`). Adding a band means adding a row, not a branch.
- Test files use a `Sut` struct at the end of the file, built per test with a constructor named by its domain argument order (`Sut::yesterday_and_now(18.0, 20.0)`). It is not shared across files (no `tests/common`) until the rule of three. Why: two files (`difference_band.rs`, `summary.rs`) share the same constructor, one short of the rule of three.
- `Summary` owns the Spanish text, built by an exhaustive `match` on `DifferenceBand` (the compiler flags a missing band). Plain `text() -> String`; `impl Display` is a later refactor candidate. Format `{:+.1}` with ASCII `-`; the parentheses with the difference always show, also for `AboutTheSame`.
- No Open-Meteo attribution is printed. Xavier's decision on 2026-10-16, accepting that the free tier's CC BY 4.0 asks for credit where the data is shown. Revisit before sharing the tool.
